# Deploying to Vercel

This app is a standard Next.js App Router project and fits Vercel's Node runtime. There is one real constraint to understand before deploying: **document storage**. Vercel's filesystem is read-only, and this build ships a local-disk storage adapter only.

Nothing in this document claims a deployment has been performed. Follow the steps and verify the result yourself.

## 1. Prepare the database

Use a hosted PostgreSQL database. [Neon](https://neon.tech) or [Supabase](https://supabase.com) both work.

- For Supabase, follow [supabase.md](supabase.md) and copy the **Session pooler** connection string (port 5432).
- For Neon, copy the pooled connection string and append `?schema=public`.

Apply the schema and seed once **from your machine**:

```bash
DATABASE_URL="postgresql://…" npx prisma migrate deploy
DATABASE_URL="postgresql://…" npm run db:seed
```

Do not seed during the Vercel build. The seed truncates tables and would reset data on every deploy.

## 2. Import the project

1. Push the repository to GitHub/GitLab/Bitbucket.
2. In Vercel, **Add New → Project** and import the repository.
3. Framework preset: **Next.js**. Root directory: the repository root (the folder containing `package.json`).
4. Build command: `npx prisma generate && npm run build` (the `postinstall` script also generates the client; being explicit avoids stale cached clients).
5. Output: default.

## 3. Environment variables

Set these for Production **and** Preview:

| Name | Value |
| --- | --- |
| `DATABASE_URL` | Hosted Postgres connection string |
| `AUTH_SECRET` | 32-byte random string (`openssl rand -base64 32`) — do not reuse the local value |
| `GEMINI_API_KEY` | Optional; enables AI extraction and summaries |
| `GEMINI_MODEL` | Optional; defaults to `gemini-2.5-flash` |
| `STORAGE_DRIVER` | Leave as `local` (see the caveat below) |

Do not add a Supabase service-role key; nothing reads it.

Changing `AUTH_SECRET` invalidates all existing sessions. Everyone signs in again.

## 4. Document storage caveat (read this)

Uploads are written under `STORAGE_LOCAL_DIR` (default `storage/`), which resolves inside the deployment bundle. On Vercel that path is read-only, so:

- **PDF uploads for requests, quotations and contracts will fail** with a storage error.
- **Seeded quotation PDFs are not in the repository** (`storage/*` is gitignored and generated by the seed), so document download links will not resolve on a fresh deployment even if uploads were possible.
- Everything else — requests, vendors, manual quotation entry, scoring, comparison, approvals, analytics, contracts, settings and audit — is database-backed and works normally.

There is no object-storage adapter in this build. To enable documents on serverless, implement `putObject`, `getObject` and `removeObject` in `src/lib/storage.ts` against S3/R2/Supabase Storage (server-side credentials only) and copy existing files into that bucket. Pointing `STORAGE_LOCAL_DIR` at `/tmp` makes uploads succeed briefly, but files are per-instance and disappear — do not present that as persistent storage.

If you need a hosted demo with documents, either deploy to a platform with a persistent volume (a small VM or container host) or add the adapter first.

## 5. Verify after deploying

1. Open the deployment URL. The landing page loads and **Sign in** reaches `/login`.
2. Sign in as `admin@opsledger.app` / `OpsLedger123!` (or another seeded user).
3. Dashboard shows seeded KPIs; open a request and confirm items, approvals and audit entries load.
4. Press `⌘K` / `Ctrl+K` and search for a vendor — live results should appear.
5. Open **Analytics** and download the CSV.
6. Confirm the demo badge is visible in the top bar.

If sign-in fails immediately after deploy, check `AUTH_SECRET` and `DATABASE_URL` in the deployment's environment scope, then redeploy.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `Can't reach database server` / `P1001` | Wrong host, paused database, or environment variable missing for the selected environment | Fix the variable scope; resume the database |
| Sessions log out instantly | `AUTH_SECRET` missing or changed between deployments | Set one stable secret per environment |
| `prepared statement already exists` | Supabase transaction pooler (6543) | Use the Session pooler (5432) |
| `ENOENT`/`EROFS` on upload | Read-only filesystem | See the storage caveat above |
| Signed out unexpectedly | Session row deleted (reseed) or `AUTH_SECRET` changed | Sign in again; keep the secret stable |
| Seed data missing | Seed was not run against the hosted database | Run `npm run db:seed` with the hosted `DATABASE_URL` |

## Cost and region notes

- Put the Vercel region close to the database to keep server-action latency low.
- Free database tiers pause when idle; the first request after a pause can be slow or fail until it resumes.
- AI calls are billed by your provider and only happen when a user runs extraction or requests a summary.
